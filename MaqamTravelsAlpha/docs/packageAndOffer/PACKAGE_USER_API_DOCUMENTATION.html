Package Module API Documentation

Enables customers to discover bundled travel packages, customize individual flight & hotel components, attach dedicated tour guides, receive real-time dynamic quotes under Option A pricing, and atomically book inventory stock units.

Base URL: /api/v1/packages
Auth: Bearer Token (JWT) for Booking endpoints
Pricing Engine: Option A (Anchored Base - Deductions + Swap Deltas + Guide)

1. Workflow & Architecture

flowchart TD
    A[Browse Packages\nGET /api/v1/packages] --> B[View Package Details & Alternatives\nGET /api/v1/packages/:id]
    B --> C[Customizer Live Quote Preview\nPOST /api/v1/packages/:id/quote]
    C -->|Opt-outs, Swaps, Guide| C
    C --> D[Book Customized Package\nPOST /api/v1/packages/book]
    D -->|JWT Auth Required| E[Stock Claimed & Master Booking Synced\nStatus: Pending]
    E --> F[List Customer Bookings\nGET /api/v1/packages/getAllBookingPackage]
    E --> G[Track Single Booking Details\nGET /api/v1/packages/bookings/:id]
    G -->|Optional| H[Cancel Booking & Release Stock\nPOST /api/v1/packages/bookings/:id/cancel]

2. API Endpoints Summary

Method Endpoint Auth Required Description
GET /api/v1/packages Public Browse, paginate, and search active packages with itemized breakdown & live availability
GET /api/v1/packages/getAllBookingPackage Bearer JWT Retrieve all package bookings for the authenticated user's profile (Alias: /bookings)
GET /api/v1/packages/:id Public Retrieve full package details, day-by-day itinerary, and eligible swappable alternatives
POST /api/v1/packages/:id/quote Public Calculate real-time customizer quote with opt-outs, swaps & guide (Option A formula)

GET /api/v1/packages/bookings/:id Bearer JWT Fetch single booking snapshot, assigned operations case officer & claimed stock units
POST /api/v1/packages/bookings/:id/cancel Bearer JWT Cancel booking, release claimed inventory units back to available stock & cancel Master Booking

3. Option A Pricing Engine

Dynamic Pricing Formula

finalSellPrice = max(0, basePackageSellPrice - totalDeductions + totalSwapDeltas + guidePrice)
totalAmount = finalSellPrice × quantity
  • Anchored Base Discount: The bundle discount (bundleDiscountPercentage) applies exclusively to bundled base items. If a guide was pre-included in the package retail price, its base fee is backed out to establish the pure base offer sum.
  • Opt-Out Deductions: Excluded optional items deduct their individual retail price multiplied by units: (offer.sellPrice × unitsPerBooking).
  • Swap Deltas: Replacement upgrades/downgrades add or subtract the exact delta: (Replacement Price × units) - (Original Price × units).
  • Tour Guide Add-on: When a guide is selected (or includeGuide: true / guideId provided), the verified guide rate is added directly without bundle discount attenuation.
  • Safety Guardrail: At least 2 Offer components must remain active per package booking. Opting out beyond this threshold triggers a 400 Bad Request.

Component Selection Mechanics: includedOfferIds vs excludedOfferIds

Individual travel components (flights, hotels) in a package are standalone Offer documents. Understanding where the keys originate and what their values represent is critical for customizer forms:

Concept excludedOfferIds includedOfferIds
Where it appears Request Body (POST /:id/quote, POST /book) & Response (customizedSelections) Request Body (POST /:id/quote, POST /book) & Response Payload (customizedSelections.includedOfferIds)
Data Type array<string> (24-char hex MongoDB ObjectIds) array<string> (24-char hex MongoDB ObjectIds)
Client Requirement Optional (pass [] if keeping all default offers) Optional (client may pass explicit Offer ObjectIds to include; any omitted optional offers are excluded)
Source of Value Selected from GET /packages/:id → priceBreakdown[].id where isOptional: true Computed: default bundled offers kept + replacement offers from swaps
Direct Meaning Opt-out list: Optional items user chose to remove from the package Active manifest: Exact items booked for which inventory units are claimed
Stock Impact No stock claimed; retail price deducted from total Physical units claimed (TicketStock, HotelStock) atomically
Guardrail Rule Cannot exclude mandatory offers (isOptional: false) Must have at least 2 active offer components (length >= 2)
⚠️
Critical ID Distinction: Always use priceBreakdown[].id (which contains the Offer's _id). Never use refId (which is the MongoDB subdocument reference ID inside offerRefs).
Example: Customized Selections in Booking Response 
"customizedSelections": {
  "includedOfferIds": [

Public
Recalculates pricing in real time based on user customizations (opting out of optional items, swapping hotels/flights, or attaching a dedicated guide). Enforces the Option A formula and the minimum 2 active offer components guardrail.
Request Body Fields
Field Type Required Description
quantity integer Optional (1) Number of package packages (must be >= 1)
excludedOfferIds array<ObjectId> Optional Opt-Out List: Array of Offer ObjectIds (string[]) to exclude (e.g. ["66d4a8e2e944f7b6b199e812"]). Must be bundled in package with isOptional: true. (Clients do not send includedOfferIds)
swappedOffers array<object> Optional List of { originalOfferId, replacementOfferId } pairings
includeGuide boolean Optional (false) Set true to attach tour guide services
guideId string (ObjectId) Optional Optional Guide model document ID to pull verified guide bio, rating & hourly/full-day rates
guideSelected string / ObjectId Optional Guide name string or Guide document ObjectId
guideLocation string / array Optional Destination or area for guide
guidePrice number Optional Custom guide price override (defaults to package guidePrice if omitted)

POST /api/v1/packages/book — Book Customized Package
Bearer JWT
Creates a customized package booking for the authenticated user, atomically claims physical wholesale stock units (TicketStock, HotelStock), freezes the immutable package snapshot, and creates/syncs a corresponding record in MasterBooking (status: "pending").
Request Body Fields
Field Type Required Description
packageId string (ObjectId) Required Target package ObjectId
quantity integer Optional (1) Number of package units (must be >= 1)
travellers array<object> Required Array of traveller objects. Exactly one must be marked isLead: true
travellers[].travellerId string (ObjectId) Required Saved Traveller profile ObjectId from /api/v1/account/travellers
travellers[].isLead boolean Required Must be true for exactly one primary contact traveller
excludedOfferIds array<ObjectId> Optional Opt-Out List: Array of Offer ObjectIds (string[]) to exclude from booking (e.g. ["66d4a8e2e944f7b6b199e812"]). Pass [] if no items are opted out. (Clients do not send includedOfferIds)
swappedOffers array<object> Optional Swapped offer pairings (originalOfferId, replacementOfferId)
includeGuide boolean Optional Set true to include dedicated tour guide service
guideSelected string Optional Guide name or identifier
guideLocation string / array Optional Destination or area for guide
guidePrice number Optional Guide fee override

curl -X POST "http://localhost:5000/api/v1/packages/book" \

POST /api/v1/packages/bookings/:id/cancel — Cancel Customer Booking
Bearer JWT
Cancels a booking in initiated or pending status, atomically releases claimed stock units (TicketStock, HotelStock) back to available wholesale inventory, sets booking status to cancelled, and synchronizes the cancellation on the linked MasterBooking.
Request Body Fields
Field Type Required Description
reason string Optional Explanation for cancellation (default: "User requested cancellation")
cURL Example 
curl -X POST "http://localhost:5000/api/v1/packages/bookings/66d4b555e944f7b6b199e825/cancel" \
  -H "Authorization: Bearer <CUSTOMER_JWT_TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{
    "reason": "Change of travel plans"

5. Error Responses Reference

All errors adhere to standard HTTP status codes and return a JSON payload with success: false and a descriptive error message:
Error Response Envelope 
{
  "success": false,
  "message": "Descriptive error message"
}
Status Code Error Message Cause / Resolution
400 Bad Request At least one traveller is required The travellers array was empty or omitted from the request body.
400 Bad Request Exactly one traveller must be marked isLead Ensure exactly one traveller in the array has isLead: true.
400 Bad Request quantity must be an integer >= 1 Quantity provided was zero or negative. Must be an integer >= 1.
400 Bad Request travellers[0].travellerId must be a valid ObjectId Provided traveller ID is not a valid 24-character hexadecimal MongoDB ObjectId.
400 Bad Request A Package must contain at least 2 Offer components... Opt-outs reduced active offers below minimum 2. Keep at least 2 components (e.g. Flight + Hotel).
400 Bad Request Offer '...' is mandatory and cannot be excluded Attempted to opt out of a non-optional item (isOptional: false).
400 Bad Request Offer '...' cannot be swapped Attempted to swap an offer that has allowSwap: false.
400 Bad Request Replacement offer ... not found or inactive The target replacement offer ID does not exist or has isActive: false.
400 Bad Request Stock reservation failed: ... Insufficient stock units remaining for a bundled flight or hotel offer.
401 Unauthorized Authentication token missing / Invalid token Pass a valid JWT customer token in the Authorization: Bearer <token> header.
404 Not Found Package not found or inactive The requested Package ID does not exist or has isActive: false / isPublic: false.
404 Not Found Booking not found The requested Booking ID does not exist or does not belong to the authenticated user.
500 Server Error Internal Server Error Unexpected server failure. Check backend application logs.
