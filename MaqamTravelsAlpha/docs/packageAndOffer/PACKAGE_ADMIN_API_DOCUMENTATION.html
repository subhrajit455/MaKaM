Package Management & Booking CRM API

Unified technical reference for creating multi-tier tour packages, profit margin analytics, optional tour guide add-ons, wholesale inventory unit claiming, and customer booking operations.

Base URL: /api/v1/crm/packages
Auth: Bearer JWT
Format: JSON (application/json)
Roles: admin, super_admin, finance, agent
Core Architectural Concepts:
  • 3-Tier Architecture: Packages bundle standalone retail Offers (Flights, Hotels, Desert Camps).
  • Guardrail: Minimum 2 Offer components required per package (e.g. Flight + Hotel).
  • Tour Guide Option: Packages support default guide configurations (guideActive, guideLocation, guidePrice). Admins can dynamically select a guide on customer bookings (includeGuide, guideSelected, guideLocation, guidePrice, guideId), seamlessly adding the guide rate to the total package booking price.
  • Stock Locking: Direct booking claims physical units into used status and initiates offline bank transfer records.

3. Error Response Reference

StatusError MessageCause / Resolution
400 Bad Request A Package must contain at least 2 Offer components... Ensure at least 2 offer references are provided in offerRefs (e.g. Flight + Hotel).
400 Bad Request Structural modifications (...) are not allowed on confirmed bookings. Attempted to swap or remove offers on an already finalized and paid booking file.
401 Unauthorized Authentication token missing / Invalid token Missing or expired JWT Bearer token in the Authorization header.
403 Forbidden Insufficient permissions The user's role is not authorized to call this endpoint.
404 Not Found Package not found / Package booking not found The specified MongoDB ObjectId does not exist.
