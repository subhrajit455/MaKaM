Cloudinary Architecture & Asset Upload Flow

Architectural reference, data flow pipelines, and integration guidelines for media and document assets (Packages, Offers, Hotels, CMS, and Visas) across the MaqamTravels enterprise platform.

1. High-Level Architecture & Pipeline

The platform implements a zero-disk, memory-buffered streaming architecture. When users or administrators upload images or document scans, files are received into temporary Node.js Buffer objects via Multer and immediately streamed over TLS to Cloudinary's global delivery edge. 

flowchart LR
    Client(["Client / Frontend"])
    Multer["Multer (MemoryStorage)"]
    Service["cloudinary.service.js"]
    Cloudinary[("Cloudinary Global CDN")]
    DB[("MongoDB")]

    Client -->|"multipart/form-data"| Multer
    Multer -->|"file.buffer in RAM"| Service
    Service -->|"upload_stream / HTTPS"| Cloudinary
    Cloudinary -->|"secure_url & public_id"| Service
    Service -->|"URLs & Metadata"| DB
⚡

Stateless & Scalable Backend

No filesystem writes or local image directories exist on the API servers. Containers can spin up, autoscale, or shut down without risk of lost uploads or disk saturation.

🌐

Global CDN Edge Caching

Every uploaded asset is instantaneously replicated and delivered via Cloudinary's distributed global points of presence with dynamic WebP/AVIF format optimization.

🔄

Safe Asynchronous Cleanup

When assets are removed or replaced (e.g. updating CMS hero banners), background fire-and-forget deletion ensures old assets are purged without blocking database operations.

🛡️

MIME & Security Isolation

Strict binary inspection in Multer prevents non-allowed file executions. Cloudinary credentials remain strictly protected in server environment variables.

2. Core Components

2.1 Configuration Layer (utils/cloudinary.js)

Initializes the official Cloudinary v2 SDK with credentials loaded securely from .env:

utils/cloudinary.js 
const cloudinary = require("cloudinary").v2;
require("dotenv").config();

cloudinary.config({
  cloud_name: process.env.CLOUDINARY_CLOUD_NAME,
  api_key: process.env.CLOUDINARY_API_KEY,
  api_secret: process.env.CLOUDINARY_API_SECRET,
});

module.exports = cloudinary;

2.2 Multer Streaming Middleware (middleware/upload.js)

Configures in-memory buffer capture and specialized MIME-type guards:

Middleware Generator Allowed File Types Default Limit Usage Example
uploadSingle("image") Images (JPG, PNG, WebP, GIF) 5 MB / 10 MB Homepage Hero banner (CMS)
uploadArray("images", 10) Images (JPG, PNG, WebP, GIF) 5 MB per file Packages, Offers, and Hotel galleries
uploadFields(fieldsArray) Images + PDFs + Word Docs 5 MB per file Visa country photos, national flags & documents

2.3 Modular Service Façade (services/cloudinary.service.js)

Clean, promise-based API methods exposed to all domain modules:

Function Parameters Return Type Description
uploadBuffer() (buffer, options) Promise<AssetObject> Streams a single binary buffer via upload_stream with folder mapping.
uploadMultipleBuffers() (files[], options) Promise<Array> Executes concurrent multi-file uploads using Promise.all.
uploadBufferToUrl() (buffer, options) Promise<string> Convenience shortcut that resolves directly to the secure HTTPS URL string.
deleteByPublicId() (publicId, type) Promise<Result> Destroys an asset permanently from Cloudinary (image, raw, or video).
extractPublicIdFromUrl() (url) string | null Strips domain, transformations, and version prefix to extract the canonical public ID.

3. Cloudinary Folder Hierarchy

To prevent naming collisions and guarantee clear access control and lifecycle policies, all assets are namespaced under the root prefix travel-agency/:

travel-agency/ ├── packages/ # Umrah & Tour package photo galleries ├── offers/ # Retail promotional deal banners and cards ├── hotels/ # Contracted & wholesale hotel property imagery ├── cms/ │ └── hero/ # Homepage landing banner image └── visas/ ├── documents/ # Applicant passport scans, photos, applicant docs ├── countries/ # Country destination photos and flags └── issued/ # Issued e-visa PDFs (stored as raw resources)
💡
Document Resources: Visas stored under travel-agency/visas/issued/ use resourceType: "raw", allowing direct PDF downloads while preserving cryptographic signatures.

4. Operational Upload Flows

4.1 Flow A: Batch Upload During Entity Creation

Admins submit form fields along with binary image files in a single multipart/form-data HTTP request (used in Packages, Offers, and Hotels): 

sequenceDiagram
    autonumber
    actor Admin as Admin / Staff
    participant Route as Express Route
    participant Multer as uploadArray("images", 10)
    participant Ctrl as Controller
    participant Service as cloudinary.service
    participant Cloudinary as Cloudinary CDN
    participant DB as MongoDB

    Admin->>Route: POST /api/v1/crm/packages (multipart/form-data)
    Route->>Multer: Process streaming multipart request
    Multer-->>Route: req.body (strings), req.files (memory buffers)
    Route->>Ctrl: adminCreatePackage(req, res)
    Ctrl->>Ctrl: Safe-parse text fields & detect req.files
    Ctrl->>Service: uploadMultipleBuffers(files, { folder: "travel-agency/packages" })
    Service->>Cloudinary: Concurrent upload_stream
    Cloudinary-->>Service: Returns secure_urls & public_ids
    Service-->>Ctrl: [{ url, publicId }]
    Ctrl->>DB: Model.create({ ...data, images: urls })
    DB-->>Ctrl: Saved document
    Ctrl-->>Admin: 201 Created (with persisted CDN URLs)

Clients upload binary files directly to obtain Cloudinary CDN URLs before submitting entity forms:

4.3 Flow C: Safe Asset Cleanup & Deletion

When an image is removed or replaced, the system extracts the public ID and deletes the asset from Cloudinary asynchronously without blocking the user response:

6. Code Implementation Patterns

6.1 Parsing `multipart/form-data` Text Fields

When uploading via multipart/form-data, arrays and objects arrive as stringified JSON. Always use safe parsers:

Safe JSON Array Parser 
const parseArrayField = (field) => {
  if (typeof field === "string") {
    try {
      return JSON.parse(field);
    } catch {
      return [field];
    }
  }
  return Array.isArray(field) ? field : [];
};

6.2 Merging Existing URLs with Uploaded Files

Allows API clients to pass both newly uploaded binary files and pre-existing Cloudinary image URLs in the same request:

Controller Upload & Merge Logic 
const files = req.files || (req.file ? [req.file] : []);
let imageUrls = parseArrayField(req.body.images);

if (files.length > 0) {
  const uploadResults = await cloudinaryService.uploadMultipleBuffers(files, {
    folder: "travel-agency/hotels",
  });
  const newUrls = uploadResults.map((r) => r.url);
  imageUrls = [...imageUrls, ...newUrls];
}

data.images = imageUrls;

6.3 Fire-and-Forget Asset Cleanup

Prevent dangling assets on Cloudinary without failing user transactions:

Asynchronous Cloudinary Destroy 
const publicId = cloudinaryService.extractPublicIdFromUrl(removedImageUrl);
if (publicId) {
  cloudinaryService.deleteByPublicId(publicId).catch((err) => {
    logger.warn(`Failed to cleanup Cloudinary asset ${publicId}: ${err.message}`);
  });
}

7. Security & Limitations

📏

File Size Ceilings

General images are strictly capped at 5 MB per file. High-resolution CMS banners are permitted up to 10 MB.

🚫

MIME Enforcement

Only trusted image types (jpeg, png, webp, gif) or documents (pdf, docx) pass through Multer.

🔐

Credentials Shielding

API secret keys are never exposed to browser clients. Signed uploads and deletions execute exclusively through backend worker endpoints.
