💳 Complete Payment Flow & Capture Explained

This standalone guide explains every single step of the payment lifecycle across Frontend, Backend, PayPal, and MongoDB.

1. High-Level Summary: The 3-Step Sequence

Every modern payment gateway (PayPal, Stripe, Razorpay) uses this 3-step sequence:

Step 1

Intent / Create Order

Backend registers intention to charge $X on PayPal.

Step 2

Customer Approval

Customer logs in to PayPal & authorizes the charge.

Step 3

Capture / Settlement

Backend pulls the money and confirms the booking.

3. What Exactly Is "Capture" & Why Is It Needed?

⚠️ Key Distinction:
Approve (Authorize): The customer gives permission. PayPal reserves/locks the funds on the customer's card. No money has moved yet.

Capture (Settle): Your backend says "Confirmed, pull the money now." PayPal actually debits the customer's card and deposits it into Maqam's merchant account. Money moves here.

4. What Happens In Code During Each Step

Step 1: Frontend calls POST /api/v1/payments/paypal/create-order

File: server/modules/payments/gateways/paypal/paypal.service.js

  • Resolves the booking using resolveBooking(bookingId, 'flight').
  • Verifies user ownership (preventing unauthorized users from paying for someone else's trip).
  • Checks if the booking is already paid (preventing accidental duplicate payments).
  • Calls PayPal API POST /v2/checkout/orders with the converted USD amount.
  • Creates a Payment record in MongoDB with status: "created".
  • Returns { paypalOrderId, redirectUrl } to the Frontend.

Step 2: Customer Approves on PayPal

  • Frontend either opens a popup with PayPal SDK or redirects to the redirectUrl.
  • Customer logs in and clicks "Agree & Pay".
  • PayPal locks the funds and sends the customer back to your frontend with the order token.

Step 3: Frontend calls POST /api/v1/payments/paypal/capture

File: server/modules/payments/gateways/paypal/paypal.service.js

  • Acquires a Distributed Redis Lock on orderId (preventing double captures from rapid clicks or concurrent webhooks).
  • Calls PayPal API: POST /v2/checkout/orders/{orderId}/capture.
  • PayPal debits customer and returns status: "COMPLETED" and captureId.
  • Executes ensureBookingConfirmed() in bookingSync.js:
    • For LCC Flight: Marks FlightBooking.status = "confirmed", links paymentId.
    • For GDS Flight: Calls SRDV ticketGDSAfterPayment() to issue live e-ticket numbers.
    • For Packages/Offers: Automatically marks claimed stock units as "used".
    • For Master Database: Creates a unified record in the Booking collection.
  • Updates Payment.status = "paid" and writes audit log.
  • Returns HTTP 200 to Frontend $\rightarrow$ Customer sees confirmation screen!
