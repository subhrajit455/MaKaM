LCC = Ticket is issued instantly at booking time, and payment is captured right after.

4. Complete Flow — GDS Flight (BullMQ Worker + Outbox)

GDS = PNR is held first with a deadline (lastTicketDate). Payment capture enqueues a background job to issue the e-ticket asynchronously without blocking the user.

5. Markup Flow — How Platform Profit Is Calculated

Stage 1: Search & Calendar

totalAmount = OfferedFare × (1 + FLIGHT_MARKUP_PERCENT / 100)
Cleaned and sent to frontend as the displayed catalog price.

Stage 2: FareQuote

Same markup formula applied to the live, locked fare snapshot returned by SRDV.

Stage 3: Booking Storage

baseTicketAmount = OfferedFare × (1 + markupPercent / 100)
totalAmount = baseTicketAmount + ancillaries (meals/baggage/seats)
markupAmount = totalAmount - OfferedFare (Saved in DB — acts as non-refundable agency fee on cancellation).

6. Cancellation, Change Request & Refund Lifecycle (Full 3-Step Flow)

💡 Markup Preservation Rule on Cancellation

When a customer cancels a flight, the platform retains the Agency Markup Fee (Maqam platform profit) and deducts the Airline Penalty returned by SRDV:

Customer Refund = Total Paid - Airline Penalty - Maqam Agency Fee Retained
Example A (₹1,100 Booking):
• Total Paid: ₹1,100 (Supplier: ₹1,000 + Maqam Fee: ₹100)
• Airline Penalty: -₹100
• Maqam Fee Retained: -₹100
• Customer Refund = ₹900
• (SRDV credits ₹900 to Maqam Wallet; Maqam refunds ₹900 via Gateway)
Example B (₹7,500 Booking):
• Total Paid: ₹7,500 (Supplier: ₹6,750 + Maqam Fee: ₹750)
• Airline Penalty: -₹2,250
• Maqam Fee Retained: -₹750
• Customer Refund = ₹4,500
• (SRDV credits ₹4,500 to Maqam Wallet; Maqam refunds ₹4,500 via Gateway)

7. SRDV Inbound Status Callback Webhook (POST /api/v1/flights/callback)

SRDV asynchronously notifies our system when a delayed booking resolves. The webhook verifies credentials, updates passenger ticket numbers on Success, and triggers a 100% full automated refund to the customer if the booking is Failed or Aborted.

sequenceDiagram autonumber participant SRDV as SRDV Supplier participant Hook as POST /api/v1/flights/callback participant DB as MongoDB participant Pay as Payment Gateway (PayPal / Razorpay) SRDV->>Hook: POST /callback { BookingId, Status: "Success" | "Failed", Passengers } Hook->>Hook: Verify ClientId, UserName, Password alt Status == "Success" Hook->>DB: Update FlightBooking.status = "confirmed", PNR, Ticket numbers Hook->>DB: Update Master Booking.status = "confirmed" Hook-->>SRDV: { Error: { ErrorCode: 0, ErrorMessage: "" } } else Status == "Failed" or "Aborted" Hook->>Pay: Trigger 100% Full Refund (No penalties) Pay-->>Hook: Gateway Refund Processed Hook->>DB: Create FlightRefund (100% refund), FlightBooking.status = "failed" Hook-->>SRDV: { Error: { ErrorCode: 0, ErrorMessage: "" } } end
